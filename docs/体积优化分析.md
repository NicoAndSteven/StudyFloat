# StudyFloat 体积优化分析

> 日期：2026-11-20  
> 基线：`dist/StudyFloat_v4`（216.8 MB）  
> 本次产物：`dist/StudyFloat_v5`（210.0 MB）+ `dist/StudyFloat_v5.7z`（63.8 MB）  
> 后续：换架构与包体积的新评估见 [架构轻量化与包体积](架构轻量化与包体积.md)（v6 保持同一体积）。

## 一、结论先行

| 方案 | 安装后（解压） | 下载包（7z） | 状态 |
|---|---:|---:|---|
| v4 改造前 | 216.8 MB | 65.3 MB | 基线 |
| **v5 本次已实现** | **210.0 MB** | **63.8 MB** | ✅ 已构建、已启动验证 |
| v5 + 去掉 yt-dlp | ≈196.5 MB | ≈60.5 MB | 需自研 B 站解析，收益主要在启动速度 |
| v5 + 定制精简 mpv | ≈150 MB | ≈48–52 MB | 唯一能大幅减小的路线，但维护成本高 |

**核心判断：**

1. 安装体积的 93% 是 **mpv（54%）+ Qt（21%）+ Python 运行时（约 12%）+ 引导 exe（6%）**，业务代码只有约 0.03%。所以“重构代码”对体积几乎没有影响，真正的杠杆只有分发压缩和 mpv。
2. 下载包从 65.3 MB 降到 63.8 MB，靠的是 Qt 深度裁剪；继续压到 60 MB 左右需要去掉 yt-dlp，代价是重写解析层。
3. 项目目录“感觉很大”主要是开发产物：`.venv` 729 MB、`build` 190 MB、`dist` 491 MB、`resources` 119 MB（其中曾有一个 32 MB 的旧 `mpv-release.7z`）。这些不是安装包内容，已清理 812 MB（仓库 223 MB + 临时文件 590 MB）。

## 三、本次已完成的轻量重构（v5）

### 1. 设置页重做（解决“太丑”）

- 单列三段式布局：**登录 / 播放 / 窗口**，640×660，无边框圆角 + 阴影。
- 自绘控件：开关（ToggleSwitch）、分段选择（SegmentedControl）、带数值的滑杆。
- 修复了旧版“黑底黑字”的根因：不再给子卡片单独 `setStyleSheet`，统一走 `QFrame#card` 全局 QSS。
- 启动器、扫码登录、分 P 选择器统一使用同一套卡片/按钮样式；空状态标签不再占位。

视觉验证：`demo_out/new_settings.png`、`new_launcher.png`、`new_parts.png`。

### 2. Qt 深度裁剪（-6.8 MB）

`tools/slim_build.py` 在 PyInstaller 之后执行，只保留：

```
Qt6Core / Qt6Gui / Qt6Widgets
QtCore.pyd / QtGui.pyd / QtWidgets.pyd
pyside6.abi3.dll + VC 运行库
plugins/platforms/qwindows.dll
plugins/styles/qmodernwindowsstyle.dll
```

删除：`Qt6Network`、`Qt6Svg`、translations、imageformats、qdirect2d/qoffscreen/qminimal、QtQuick/Qml/Pdf（PyInstaller 会误收）。

结果：`PySide6 46.45 → 39.63 MB`，安装目录 `216.8 → 210.0 MB`。

> 修正一个此前的误判：旧 `build.spec` 末尾的 Qt 清理**确实生效**（v4 里没有 QtQuick，正是它删掉的）。问题在于它把清理写死在 spec 里、范围也偏保守，现已移出为独立脚本，构建流程更清晰。

### 3. 启动路径优化

- 设置窗口不再 `import app.main`（否则会连锁导入 yt-dlp/curl_cffi）；新增 `app/paths.py`。
- `bilibili_parser`、`bilibili_parts`、`bili_login`、`qrcode` 改为用到时才导入。
- 实测 `python -X importtime -c "import app.main"`：**1.80 s → 0.47 s**（仅 import 阶段，不含 Qt 窗口和 mpv 启动）。

### 4. 构建/分发工具

- `tools/slim_build.py`：构建后裁剪 Qt，幂等、可重复执行。
- `tools/package.py`：一键生成 `dist/StudyFloat_v5.7z`（7zr，`-mx=9`）。
- 验证：`pytest tests -q` → **47 passed**；冻结后的 `StudyFloat_v5.exe` 可正常启动并渲染（已截图确认）。

## 四、可选方案评估

### A. 清理开发产物（已完成）

| 项目 | 清理前 | 处理 |
|---|---:|---|
| `build/` | 190.3 MB | 已删除（可重建） |
| `resources/mpv/mpv-release.7z` | 32.4 MB | 已删除（旧下载缓存） |
| 截图迭代脚本 / 失败探针 | <0.1 MB | 已删除 |
| `%TEMP%` 体积模拟目录 | 589.5 MB | 已删除 |
| `demo_out/` | 1.2 MB | 保留，已加入 `.gitignore` |

`.venv`（729 MB）是开发环境，不随包分发；用 `uv sync` 可重建。  
`dist/StudyFloat_v4`（217 MB）建议在确认 v5 后删除，可再省 217 MB。

### B. 压缩分发（推荐，已实现）

- 7z `-mx=9`：210.0 MB → **63.8 MB**（3.29×）。
- 如果做安装器（Inno Setup / NSIS + LZMA2 solid），预计 **64–68 MB**，主要多出安装/卸载逻辑，压缩率与 7z 接近。
- 不建议 zip：同样内容约 75 MB 以上，且没有固实压缩。
- 安装器的额外价值是快捷方式、卸载、静默升级；代价是需要代码签名，否则 SmartScreen 会提示未知发布者。

### C. 去掉 yt-dlp（可选，收益有限）

`yt_dlp 9.55 + Cryptodome 1.57 + sqlite 1.52 + brotli 0.83 + 杂项 ≈ 13.5 MB`，压缩后只省约 **3.3 MB**。

可行性：项目已经在用 `curl_cffi` 调 B 站 `passport` 和 `view` API，补一个 `playurl` 解析器即可覆盖普通视频/分 P；番剧、8K/HDR、Dolby、字幕轨道需要额外适配。

- 收益：下载 -3.3 MB、冷启动再快约 1 s、减少误报。
- 成本：解析层重写 + 回归测试，约 1–2 周；B 站改版时要自己维护。
- 建议：**只有确定“永远只做 B 站”时才做**，理由是可控性和启动速度，不是体积。

> 单纯裁剪 `yt_dlp/extractor` 下 941 个文件可省约 7.3 MB，但 `lazy_extractors.py` 在解析某些类时会导入无关 extractor，容易“今天能播、明天某个视频炸”，不建议作为发布步骤。

### D. 替换 PySide6（不推荐）

PySide6 39.6 MB（18.8%）。换 Tkinter 理论上省 30 MB 左右，下载包省 8 MB 左右，但会直接毁掉这次重做的 UI（圆角、阴影、开关动画、统一 QSS 都无法复现），而且是一次全量重写。**与“设置页太丑”的诉求直接冲突，否决。**

### E. 精简 mpv（唯一的大杠杆，但重）

- 现状：117.6 MB，占安装体积 54%；7z 后约 32 MB，所以它对**下载包**的影响远小于对安装目录的影响。
- B 站播放实际只需要：H.264/HEVC/AV1 解码、AAC/Opus/FLAC、libass 字幕、`gpu-next` 渲染、IPC、`ytdl_hook`。
- 定制构建（关掉编码器、无用滤镜、多余输出设备）粗估可到 50–70 MB → 总安装 145–165 MB，下载包 45–52 MB。
- 代价：MSYS2 交叉编译链、显卡/驱动兼容回归、每次 mpv 升级都要重打。**不属于“轻量重构”。**
- 预编译的 LGPL 精简版：本次 release 只提供 `mpv-dev-lgpl`，没有纯 `mpv-lgpl`；GitHub 下载在当前网络下只有约 8 KB/s，未能验证，不能作为结论。
- UPX：不推荐。mpv 的 `.text` 有 94 MB，UPX 会在启动时整段解压，拖慢播放器启动，且容易触发杀软误报；7z 已经能压到 32 MB。
- onefile：不推荐。每次启动解压到临时目录，启动更慢，体积也不会更小。

### F. 其他小项

- 移除 QtNetwork/QtSvg：已做（约 -4 MB 原始）。
- `libcrypto/libssl` 不能删：`curl_cffi` 顶层 `import ssl`。
- `--strip` 在 Windows 上无效；Qt DLL 再 UPX 收益低、风险高。
- `qrcode.tests` 被 PyInstaller 分析进来，但只占约 0.1 MB，不值得处理。

## 六、建议路线

**现在（已完成）**

1. 用 v5 作为发布版：`dist/StudyFloat_v5/` + `dist/StudyFloat_v5.7z`。
2. 分发用 7z 便携包；确认 v5 稳定后删除 `dist/StudyFloat_v4`（再省 217 MB）。
3. 保持 yt-dlp，不为 3 MB 下载体积去重写解析层。

**下个版本（可选）**

4. 做 Inno Setup 安装器 + 自动更新；如面向普通用户，考虑代码签名。
5. 如果确定只做 B 站，再做原生 `playurl` 解析，去掉 yt-dlp（顺带缩短启动、减小误报）。

**不建议**

- 换 Tkinter（毁 UI，省得也不多）。
- UPX / onefile（启动变慢、杀软风险）。
- 自己编译 mpv（除非有持续维护构建链的精力，或用户量足够大）。

# StudyFloat 架构轻量化与包体积评估

> 日期：2026-11-20
> 基线：`dist/StudyFloat_v5`（安装后 210.0 MB，7z 63.8 MB）
> 口径：Windows 资源管理器 MB（实为 MiB）；7z 为 `-mx=9` 固实压缩实测。

## 一、结论先行

| 路线 | 安装后 | 7z 下载 | 工程量 | 评价 |
|---|---:|---:|---|---|
| 现状 v5（PySide6 + mpv + yt-dlp） | 210.0 MB | 63.8 MB | — | 基线 |
| A. 只做瘦身：去 yt-dlp | 196.5 MB | 60.5 MB | 1–2 周 | 已实测，收益主要不在体积 |
| B. 只做瘦身：定制精简 mpv（60 MB） | ≈152 MB | ≈48–52 MB | 2–4 周 | **性价比最高的减重** |
| C. A + B | ≈139 MB | ≈44–46 MB | 3–5 周 | 保留全部播放能力 |
| D. 换原生壳（Tauri/Rust）+ 完整 mpv | ≈125–132 MB | ≈36–39 MB | 6–8 周 | UI 重写，播放不动 |
| E. 换原生壳 + 精简 mpv（60 MB） | ≈63–70 MB | ≈19–22 MB | 8–12 周 | 进 20 MB 的可行路线 |
| F. 去掉 mpv，WebView2 + MSE 播放 | ≈6–10 MB | ≈3–5 MB | 8–12 周 | 唯一数量级下降，但播放能力降级 |
| G. FFmpeg 最小构建 + 自绘播放器 | ≈32–40 MB | ≈10–14 MB | 12–16 周 | 工程量最大，风险最高 |

> D/E 的 125–132 MB / 63–70 MB 是「B 站专用、去掉 yt-dlp」的前提。要继续支持 YouTube 等多站点，yt-dlp 必须跟着走，D/E 会抬到约 140–145 MB / 41–44 MB（完整 mpv）与 78–85 MB / 25–28 MB（精简 mpv），见第八节。

**三句话：**

1. **UI 框架不是体积瓶颈。** 安装体积的 56% 是 `mpv.exe`（117.6 MB），Qt 只占 18.9%。把 Qt + Python + 引导器全换掉，安装省约 60–70 MB，7z 只省约 25 MB。
2. **下载体积的一半也是 mpv。** mpv 压缩后约 32 MB，占 63.8 MB 下载包的 50%；业务代码只有约 0.2 MB。所以「重构代码」对包体积几乎没有影响。
3. **真要进 20 MB，必须动 mpv。** 要么换成精简 mpv 构建 + 原生壳（≈20 MB），要么彻底不打包 mpv、改用系统 WebView2（≈4 MB）。后者会丢掉 HEVC/4K/HDR、ASS 字幕和 mpv 的控制能力。

**建议：** 这一版不改架构。先用「定制精简 mpv」把下载压到 48–52 MB；如果未来把「下载 < 30 MB」定成硬指标，再考虑 Tauri + 精简 mpv（≈20 MB）。不建议为了 20 MB 去换 Tkinter/WPF，也不建议在没有把握前自己写播放器。

## 二、v5 实测构成

| 组件 | MB | 占安装体积 | 说明 |
|---|---:|---:|---|
| `resources/mpv/mpv.exe` | 117.62 | 56.0% | 静态编译完整 mpv，含 FFmpeg 全编解码器、libplacebo、libass |
| `PySide6/` | 39.63 | 18.9% | 已裁到 QtCore/QtGui/QtWidgets + qwindows 插件 |
| `StudyFloat_v5.exe` | 13.05 | 6.2% | PyInstaller 引导器 + 打包的 Python 字节码 |
| `yt_dlp/` | 9.55 | 4.5% | 941 个 extractor，实际只走 Bilibili |
| Python 运行时（`python312.dll`、`base_library.zip`、`unicodedata` 等） | ≈13.8 | 6.6% | 解释器与标准库 |
| `libcrypto-3-x64.dll` + `libssl-3-x64.dll` | 9.12 | 4.3% | `curl_cffi` 依赖 |
| `curl_cffi` + `.libs` | 4.42 | 2.1% | TLS 指纹 + libcurl |
| `Cryptodome` + `sqlite3` + `brotli` 等 yt-dlp 依赖 | ≈4.6 | 2.2% | |
| `qrcode` | 0.11 | 0.1% | 二维码矩阵 |
| 其他（shiboken、pyexpat、VC 运行库等） | ≈3.0 | 1.4% | |
| **合计** | **210.0** | 100% | |

压缩实测：

- 安装 210.0 MB → 7z 63.8 MB（**3.29×**）。
- mpv 117.62 MB → 约 32 MB（**3.67×**）。
- 其余 92.38 MB → 约 31.8 MB（**2.90×**）。

> 下文所有「换架构」估算都按这两个压缩率外推，误差约 ±10%。真实构建会因编译器、运行库、资源不同而浮动。

**按层看：**

- 播放引擎 117.6 MB（56%）—— 真正的产品护城河，也是最大的减重对象。
- UI + 解释器 + 引导器 ≈66.5 MB（31.7%）—— 换壳能省的部分。
- B 站解析 + TLS ≈22.3 MB（10.6%）—— 只做 B 站可以重写成 2–4 MB。
- 业务代码 0.2 MB —— 可忽略。

## 三、为什么「换 UI 框架」省不了多少

很多人对「换架构」的直觉是：Qt 很重，换掉就轻了。实际账不是这样。

- 安装体积：Qt 39.6 MB + Python 运行时 13.8 MB + 引导器 13.05 MB ≈ **66.5 MB**。
- 下载体积：这 66.5 MB 按 2.9× 压缩，约 **23 MB**；再加新壳本身的 3–5 MB，净省 **18–20 MB**。
- 结论：**63.8 MB → 36–39 MB**，降幅约 40%；不是「降一个数量级」。

而 mpv 一项：

- 安装 117.6 MB，下载约 32 MB。
- 把 mpv 从 117.6 MB 压到 55–60 MB，下载直接少 **15–17 MB**，和「换掉整个 Qt + Python」的收益同一量级，但不用重写 UI。
- 彻底不打包 mpv，下载才可能到 **3–5 MB**。

所以减重的优先级应该是：

```
mpv 构建 > 去掉 yt-dlp > 换 UI 壳 > 重构业务代码
```

业务代码重构对体积的贡献是 0；它的价值在启动速度、可维护性和未来换壳的成本。

## 四、各路线详解

### A. 保留 PySide6，只做依赖瘦身

**A1 去 yt-dlp（已实测）**

- 删除 `yt_dlp / Cryptodome / sqlite3 / brotli` 等，安装 196.5 MB，7z 60.5 MB。
- 需要自己实现 B 站 `playurl`：`view` 拿 cid，`x/player/wbi/v2` 拿 DASH 视频/音频直链，补 WBI 签名与 Referer。
- 收益：下载 −3.3 MB、冷启动再快约 1 s、减少杀软误报。
- 代价：番剧、8K/HDR、Dolby、字幕轨道要逐项适配；B 站改版要自己维护。
- 判断：**只有确定「永远只做 B 站」才值得做**，理由是可控性和启动速度，不是体积。

**A2 定制精简 mpv（最大单点杠杆）**

- 现成构建 117.6 MB 包含：全部解码器、全部编码器、全部滤镜、CUDA/NVENC、VapourSynth、JavaScript、libarchive、多种输出设备。
- B 站播放实际只需要：H.264 / HEVC / AV1 / VP9 解码，AAC / Opus / FLAC，Matroska/MP4/FLV 解封装，libass，`gpu-next`（D3D11/Vulkan），WASAPI，JSON IPC。
- 用 MSYS2 自编译，关掉编码器、无用滤镜、无用输出设备，粗估 **55–65 MB**。
- 安装：210 − 117.6 + 60 ≈ **152 MB**；7z：63.8 − 32 + 16 ≈ **48 MB**（区间 48–52）。
- 代价：构建链、驱动/显卡兼容回归、每次 mpv 升级要重打；不属于「轻量重构」。
- 不建议 UPX（`.text` 90 MB+，启动整段解压，杀软风险高）；不建议 onefile（每次启动解压到临时目录，更慢）。

**A3 A1 + A2**：安装 ≈139 MB，7z ≈44–46 MB，播放能力不减。

### B/C. 换原生壳（Tauri / Rust）+ mpv

**B 保留完整 mpv**

| 组成 | MB |
|---|---:|
| mpv.exe | 117.6 |
| Tauri/Rust 壳 + WebView2 loader | 3–5 |
| 原生 B 站解析（Rust/Go） | 2–3 |
| 资源/图标/VC 运行库 | 2–3 |
| **安装** | **≈125–132** |
| **7z** | **≈36–39** |

- 收益：比现状少约 80 MB 安装 / 25 MB 下载；UI 可以用 HTML/CSS 做，设计还原度高。
- 代价：Qt 版 UI 要重写成 Web 前端；需要 Rust 后端 + WebView2；B 站解析要从 Python 迁移。
- 注意：WebView2 Runtime 在 Win10 21H2+ / Win11 通常预装，但 LTSC、Server、精简系统可能没有；固定版 WebView2 运行时约 +130 MB，等于白换。

**C 再加精简 mpv（55–60 MB）**

- 安装 ≈63–70 MB，7z ≈19–22 MB。
- 这是「下载 < 25 MB」目标下最现实的组合：保留 mpv 的播放质量，只牺牲 UI 框架。
- 工程量：8–12 周（壳 4–6 周 + 解析 2 周 + 精简 mpv 2–4 周 + 回归）。

### D. 不打包 mpv：WebView2 + MSE 播放

- 壳 3–5 MB + HTML/JS 播放器 1–2 MB + 原生解析 2 MB ≈ **6–10 MB 安装 / 3–5 MB 7z**。
- 播放走 `<video>` + MSE（shaka-player / dash.js），自己拼 B 站 DASH 的 video/audio 分轨。
- **代价（按当前产品承诺逐条对照）：**
  - HEVC 在 WebView2 里默认不可用（依赖系统 HEVC 扩展/硬件），4K/HDR/杜比视界基本告别。
  - AV1 可用，但软解占用高；H.264 1080p 没问题。
  - ASS 字幕需要 JS 渲染库，效果不如 libass；多音轨、音频直通要自己做。
  - 没有 mpv 的 OSC、`gpu-next`、色彩管理、去隔行、硬件解码回退链。
  - 播放窗口仍然是独立窗口，这点可以保留。
- 判断：**只有明确接受「1080p AVC 为主、不要 4K/HDR」才成立**。否则它会把产品从「真播放器」降级成「网页播放器」。

### E. FFmpeg 最小构建 + 自绘播放器

- 只保留 h264/hevc/av1/aac/opus + d3d11va + wasapi，DLL 约 25–30 MB；壳 5 MB；合计 **32–40 MB 安装 / 10–14 MB 7z**。
- 但「播放器」不只是解码：同步、seek、变速、字幕、HDR、音频输出、窗口管理都要自己写。
- 12–16 周起步，且很难达到 mpv 的稳定性。除非有长期播放器团队，不建议。

### F. 不推荐的换法

| 方案 | 结果 | 原因 |
|---|---|---|
| Tkinter + 去 yt-dlp | ≈166 MB / ≈52 MB | 省 8 MB 下载，但圆角、阴影、动画、统一 QSS 全部做不出来，和「UI 太丑」的诉求直接冲突 |
| Electron | +100 MB 以上 | 比 Qt 更重 |
| WPF/.NET 自包含 | ≈160 MB / ≈48 MB | WPF 运行库自包含约 35–45 MB，减重不如 Tauri |
| WinUI 3 | ≈150 MB | Windows App SDK + .NET 运行时 |
| UPX / onefile | 体积不变或更大 | 启动变慢、杀软误报 |

## 五、如果要做，架构应该怎么切

### 5.1 代码分层：core / adapters / shell

当前 `app/` 已经是 `source / player / ui / window` 的分层，但 `main.py` 同时做编排、UI 回调和播放器启动，换壳时会牵一发动全身。建议切成：

```
app/
├── core/                 # 纯领域，不 import Qt / mpv / HTTP
│   ├── models.py         # Video / Part / Stream / PlaybackRequest
│   └── service.py        # PlaybackService：校验 → 选P → 解析 → 起播
├── adapters/
│   ├── bilibili/         # client.py（curl_cffi）、wbi.py、playurl.py
│   ├── mpv/              # controller.py（命名管道 IPC）
│   └── storage/          # config.py、cookie.py、geometry.py
├── shell/                # Qt 窗口（未来可整体替换）
│   ├── launcher.py
│   ├── settings_dialog.py
│   └── widgets.py
└── platform/             # paths、单实例、日志
```

收益（与体积无关，但决定「换架构」的成本）：

- 换 UI 壳只动 `shell/`，`core` 与 `adapters` 原样复用；
- 换解析器只动 `adapters/bilibili/`，UI 无感；
- `core` 可以纯 pytest 覆盖，不再依赖真实网络与 mpv 进程；
- 未来做 Tauri/Rust 壳时，`core` 的接口定义可以直接翻译成 IPC 契约。

### 5.2 解析层：原生 B 站客户端（仅 B 站专用 Micro 版需要）

> 全站版保留 yt-dlp；本节只适用于额外发行的「B 站专用 Micro 版」，不作为主版本路线。

需要覆盖的接口：

1. `GET /x/web-interface/view?bvid=` → 标题、cid、分P 列表（`pages`）。
2. `GET /x/player/wbi/v2?bvid=&cid=&qn=&fnval=4048` → DASH：`video[]` / `audio[]` 的 `baseUrl`、`backupUrl`、codecid、id。
3. WBI 签名：`img_key` + `sub_key` 混淆表 + `w_rid`；缓存每日 key。
4. 请求头：`Referer: https://www.bilibili.com/`、UA、`SESSDATA`（可选）。
5. 失败回退：412 风控、版权/地区限制、登录失效，要有明确中文错误。

这套东西约 300–500 行，带 20–30 个单测即可覆盖普通视频/分P/清晰度选择。收益是去掉 13.5 MB 依赖与约 1 s 冷启动；风险是 B 站改版要跟。

### 5.3 壳的选型（如果真要换）

| 壳 | 安装增量 | UI 能力 | 风险 |
|---|---:|---|---|
| Tauri（WebView2 + Rust） | 3–5 MB | HTML/CSS，最接近当前设计稿 | WebView2 依赖、Rust 学习成本 |
| Rust 原生（egui/slint） | 3–8 MB | 中；中文排版与圆角阴影要自己处理 | 难做到「精致」 |
| C++ Win32/D2D | 2–5 MB | 高，但全部自绘 | 开发慢 |
| WPF | 35–45 MB | 高 | 省得少 |
| Tkinter | ≈0（Python 自带） | 低 | 与当前 UI 目标冲突 |

结论：**要换壳就选 Tauri**；否则留在 Qt。

### 5.4 「按需下载 mpv」不等于变小

把 mpv 从安装包拿掉，首包可以降到 92.4 MB / 31.8 MB 7z，首次启动再下载 32 MB 的 mpv。用户总下载量不变，只是把「一次 64 MB」拆成「32 MB + 32 MB」。它改善的是首包门槛，不是总流量；需要 CDN、断点续传、校验和离线包回退。

## 六、建议路线

**这一版（已完成）**

- UI 重做：暖夜色 + 黄铜单强调色，启动器/设置/分P/扫码四窗口统一。对包体积影响 0。
- 保持 PySide6 + mpv + yt-dlp 的架构，先不为了 20 MB 重写。

**下一版（如果继续做减重）**

1. **S1（2–4 周）**：定制精简 mpv 到 55–60 MB → 安装 ≈152 MB、下载 ≈48–52 MB。这是投入产出比最高的一步。保留 yt-dlp，多站点能力不变。
2. **S2（可选，6–10 周）**：Tauri + 精简 mpv + 独立 `yt-dlp.exe` → 安装 ≈78–88 MB、下载 ≈24–28 MB。UI 需要重写，yt-dlp 首次解析多 1–2 s。
3. **S3（可选，独立产品线）**：Tauri + 精简 mpv + 原生 B 站解析，做「B 站专用 Micro 版」→ 安装 ≈63–70 MB、下载 ≈19–22 MB。它是额外版本，不替代全站版。
4. **S4（仅当接受播放降级）**：WebView2 + MSE，不打包 mpv → 安装 ≈6–10 MB、下载 ≈3–5 MB。

> 原「S2 去 yt-dlp」已按用户决策移除：产品不只服务 B 站，全站版必须保留 yt-dlp。

**不做**

- 为体积换 Tkinter / WPF：省得少，毁 UI。
- UPX / onefile：启动慢、杀软风险。
- 在 S1 之前换壳：mpv 还在，换了也只降 40%。

## 七、测量与估算口径

- 安装体积：`Get-ChildItem <dir> -Recurse -File | Measure-Object Length -Sum`。
- 下载包：7-Zip 26.06 `7zr a -t7z -mx=9 -mmt=on`，与 `tools/package.py` 一致。
- 组件表为 v5 目录实测；`PySide6` 已经过 `tools/slim_build.py` 裁剪。
- 换架构的 7z 数字按「非 mpv 2.90× / mpv 3.67×」外推；实际受新壳二进制、资源、编译器影响，误差 ±10%。
- 「精简 mpv 55–60 MB」是构建预估，未在本机验证；需要在 MSYS2 环境打出第一版后复测。

## 八、补充：保留多站点解析时，Tauri 的数字要重算

第二节 D/E 的 125–132 MB / 36–39 MB 前提是「B 站专用、去掉 yt-dlp」。如果产品要继续支持 YouTube 等站点，yt-dlp 必须跟着走，而 yt-dlp 是 Python 程序。换 Tauri 后有两种带法：

| 带法 | 安装增量 | 7z 增量 | 代价 |
|---|---:|---:|---|
| 独立 `yt-dlp.exe`（PyInstaller onefile） | +17–20 MB | +5–6 MB | 每次解析先解压，首次起播多 1–2 s |
| 保留 Python 运行时 + yt-dlp 库 | +30–40 MB | +10–14 MB | Tauri 相对 Qt 只剩约 20 MB 优势，还要维护两套运行时 |

修正后的全站版数字：

| 路线 | 安装后 | 7z |
|---|---:|---:|
| Tauri + 完整 mpv + yt-dlp.exe | ≈140–147 MB | ≈41–45 MB |
| Tauri + 精简 mpv + yt-dlp.exe | ≈78–88 MB | ≈24–28 MB |
| Tauri + 精简 mpv + 原生 B 站（无 yt-dlp） | ≈63–70 MB | ≈19–22 MB |

结论：**20 MB 下载只属于「B 站专用 Micro 版」**。全站版换 Tauri 的真实收益是 41–45 MB（完整 mpv）或 25–28 MB（精简 mpv），不是 20 MB；再叠加 6–10 周 UI 重写与 yt-dlp 启动损耗，优先级应排在精简 mpv 之后。

## 九、按功能范围分版本（建议）

一套代码，用打包参数切三种「功能范围」，而不是维护三套代码：

| | Full 完整版 | Standard 标准版 | Micro 微型版（可选） |
|---|---|---|---|
| 壳 | Qt（现有 v6 UI） | Qt（现有 v6 UI） | Tauri |
| mpv | 官方完整构建 117.6 MB | 精简构建 55–60 MB | 精简构建 55–60 MB |
| 解析 | yt-dlp 全站 | yt-dlp 全站 | 原生 B 站 |
| 解码 | 全部（含 VC-1/MPEG-2/ProRes 等） | 主流：H.264/HEVC/AV1/VP9/AAC/Opus/FLAC/MP3 | 同标准 |
| 硬解 | 全部路径（D3D11VA/DXVA2/NVDEC） | D3D11VA/DXVA2（NVDEC 可选） | D3D11VA |
| 4K/HDR | 是 | 是（取决于显卡与片源） | 是（取决于显卡） |
| 字幕 | libass | libass | libass |
| 截图 | 是 | 是（保留 PNG/JPEG 编码器，约 +1 MB） | 否 |
| 录制/转码 | 是（mpv 能力，UI 暂未暴露） | 否 | 否 |
| 滤镜 | 全部 libavfilter | 仅基础兼容（format/scale） | 仅基础兼容 |
| 额外输出 | 全部 vo/ao | gpu-next/gpu/direct3d + WASAPI/DirectSound 回退 | 同标准 |
| 安装后 | 210 MB | ≈152 MB | ≈65 MB |

**推荐落地顺序**

1. **先做 Full + Standard，共用现有 Qt 壳**：只增加一个 `mpv` 精简构建和打包参数，UI 不动，1–2 周可出 Standard 包。这也是用户要的「不同功能范围发行版」最低成本实现。
2. **Micro 作为独立产品线**：只有「下载 < 20 MB」成为硬指标时再做；它需要 Tauri + 原生 B 站解析，等于第二个产品，不适合和主版本同时维护。
3. **Tauri 全站版（S2）排在精简 mpv 之后**：24–28 MB 的收益要用 6–10 周 UI 重写换，投入产出比不如先把 Standard 跑通。

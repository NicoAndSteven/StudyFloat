# StudyFloat 验证记录

## 验证 A：Bilibili 视频解析（yt-dlp）

- 日期：2026-11-19
- 环境：Python 3.12（项目 `.venv`），yt-dlp 2026.10.26
- 命令：
  ```
  .venv\Scripts\python.exe tools\parse_probe.py "https://www.bilibili.com/video/BV1GJ411x7h7"
  ```
- 结果：**通过**。无需登录成功解析到直链。
  - 标题：哔哩哔哩 MV《Never Gonna Give You Up - Rick Astley》
  - 时长：212.393 秒
  - `http_headers`：含 `Referer: https://www.bilibili.com/video/BV1GJ411x7h7`（播放时需传给 mpv）
  - 格式：全部为 DASH（视频流 + 音频流分离），**无音视频合并格式**。
    - 音频：30216 (mp4a.40.5)、30232/30280 (mp4a.40.2)
    - 视频：30016 (640×360 avc1)、30032 (852×480)、30064 (1280×720)、30080 (1920×1080)，另含 HEVC/AV1 同分辨率流
    - 免登录即返回 1080p 直链（该视频授权公开），说明当前 yt-dlp 对部分视频可直接拿到高清晰度；仍不保证所有视频如此。
- 结论：解析器需走 **DASH 路径**（video-only 直链 + audio-only 直链，用 mpv `audio-add` 外挂音轨）。合并格式优先逻辑保留，兼容未来/其他来源。
- 备注：未遇到 HTTP 412 / 反爬拦截。若后续遇到，按 spec §7 走 Cookie 文件路径。

## 验证 C：窗口与播放控制（IPC）

- 工具：`tools/ipc_probe.py`（Windows 命名管道 `\\.\pipe\studyfloat_probe`，换行分隔 JSON，request_id 匹配响应）。
- 结果：**通过**（关键命令实测）：
  - `get_property pause/time-pos/duration/geometry/border/ontop` → 全部 `success`；`time-pos=17.7`、`duration=212.261`、`geometry=480x270+100+100`、`border=False`、`ontop=True`。
  - `set pause false/true`、`seek 5 relative`、`set speed 1.5`、`set volume 60`、`set mute true/false` → 全部 `success`；`time-pos` 从 17.7 前进到 25.8，证明播放/跳转真实生效。
  - `set_property border/ontop` 切换 → `success`，窗口外观随之变化。
  - `quit` → mpv 进程正常退出。
- **重要修正**：DASH 外挂音轨命令为 `audio-add <url>`（仅两个参数）；`audio-add <url> external audio` 返回 `invalid parameter`。执行后 `aid=1`、`track-list/count=2`，音轨加载成功。实现时须用两参数形式。
- 通过标准：所有命令返回正确 `error`；属性读取与播放状态一致；控制生效。✅

## 扫码登录（新增，免复制粘贴 Cookie）

- 日期：2026-11-19
- 背景调查（实测）：
  - 本机 Chrome(157) 内有 B站登录 Cookie（SESSDATA/bili_jct/DedeUserID 等），但加密值前缀为 `v20` = **App-Bound Encryption**，yt-dlp `cookiesfrombrowser` 报 "Failed to decrypt with DPAPI"；指定 profile 时还遇到数据库被浏览器进程独占锁定。**自动读取浏览器 Cookie 在 Chrome 127+ 上不可行**（Edge 同样锁定，本机无 Firefox）。
  - yt-dlp 源码确认：判断登录态只看 `SESSDATA` 一条；`buvid3` 缺失会自动生成。
- 方案：改用 B站官方 passport 扫码登录接口，绕开浏览器 Cookie 加密。
- 实测结果：
  - `GET /qrcode/generate`：用 curl_cffi 模拟浏览器 TLS 指纹时成功（HTTP 200, code=0），普通 urllib 会被 SSL 拒绝 → 已用 curl_cffi 并内置 3 次重试。
  - `GET /qrcode/poll`：未扫码时正确返回 86101（等待）。
  - cookie 格式链路：扫码结果写成 Netscape `cookies.txt` 后，用 `YoutubeDL(cookiefile=...)` 成功加载全部 4 条 cookie（domain `.bilibili.com`）。✅
  - 单元测试：7 个（mock 网络，覆盖 generate/状态机/cookie 格式）全部通过。
- **已知限制**：测试环境出口 IP 对 passport 接口出现临时限流（多次请求后 TLS 连接被拒，成功率波动）；这是服务端风控，真实家庭 IP 正常。已加重试与友好错误提示。若限流持续，等几分钟或换网络即可。
- 说明：真正的"扫码→手机确认→拿到 SESSDATA"全链路需要用户用手机扫码，本环境无法自动完成；已验证到"生成二维码 + 轮询接口 + cookie 落地解析器"的每一环。

## Bug 修复：多P视频解析无响应（2026-11-19）

- 现象：用户扫码登录后粘贴 `BV1qG41197E4...&p=18`，解析长时间无响应。
- 根因（A/B 对比实测）：`normalize_url` 用正则提取 BV 号后重建干净 URL，**剥离了 `?p=18`**。该视频是多P合集，不带 p 时 yt-dlp 会枚举整个合集 → 75 秒以上不返回。带 `p=18` 时 **1.4 秒**即成功（标题为 p18 那一P）。
- 修复：`normalize_url` 保留 p 参数（p>1）；新增 2 个失败测试再修好。修复后完整链路 1.4 秒返回，36 个测试全通过。
- 备注：重建时旧打包目录里的 `qr_cookies.txt` 被清理，需在新版重新扫一次码（几秒）。交付目录改为 `dist/StudyFloat_v2`（旧目录被 Windows 句柄锁定无法删除，不影响使用）。
